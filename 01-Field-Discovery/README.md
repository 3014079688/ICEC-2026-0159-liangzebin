# 阶段一 · Field Discovery（实地发现）

> 目的：用**真实的一手证据**证明「这个痛点真的存在」，而不是拍脑袋想出来的。

## 本目录放什么

| 位置 | 内容 |
| --- | --- |
| `报告.md` | 调研报告正文（见下方结构） |
| `images/` | 现场照片、手绘草图、访谈截图、竞品截图 |
| `raw_data/` | 原始素材：问卷导出、访谈记录转写、场景测量数据、日志表格 |

## 报告.md 建议结构

1. **痛点描述** —— 谁在什么场景下遇到了什么麻烦？麻烦有多大（时间/金钱/安全风险）？
2. **现场证据** —— 照片、访谈原话、实测数据。**每条结论后面挂一个证据来源**。
3. **已有方案与不足** —— 现在人们是怎么凑合解决的？竞品/现有产品差在哪？
4. **需求收敛** —— 从上面几条里，收敛出 1 个你要解决的核心问题。
5. **初步假设** —— 你的解决方案假设是什么？哪些还没被验证？

## 提交检查清单

- [ ] 报告里至少有 **3 条一手证据**（照片 / 访谈 / 实测数据）
- [ ] 每条关键结论都标注了来源文件名
- [ ] 原始数据放进 `raw_data/`，不要只放处理后的结论
- [ ] 图片用有意义的文件名（`interview-01.jpg` 而不是 `IMG_2026.jpg`）
- [ ] 已 `git add . && git commit && git push`
